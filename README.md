# Triage Desk

AI support triage for multi-brand D2C stores. Every inbound customer message is stored, triaged by a Claude orchestrator agent with specialist sub-agents, and shown to staff with a policy-grounded draft reply they approve in one click. n8n moves the data, Supabase keeps each brand's data isolated with Row Level Security, and a Next.js dashboard on Vercel is where the team works.

Demo brand: [Miau Atelier](https://miauatelier.com) (real policies and catalog), plus a fictional second brand to show brand isolation.

**Design:** [docs/TDD.md](docs/TDD.md) covers architecture, data model, the RLS matrix, the agent design, workflows, environments, testing and risks.

## How it works

1. An email parser, contact form or `scripts/send-demo-messages.mjs` posts the message to the **n8n** inbound webhook.
2. n8n stores it through an idempotent RPC and calls the **triage edge function**.
3. The **orchestrator** (Claude Opus 5.5) reads the message, looks up the order, and asks the **policy** and **product** specialists, each a sub-agent that sees only its own source. It returns a structured triage record: category, priority, sentiment, summary, confidence, whether a human is needed and why, and a draft reply in the brand voice.
4. The **dashboard** updates live (Supabase Realtime). Staff edit and approve, or escalate.
5. Approval fires a Postgres trigger (`pg_net`) that calls the n8n **send** workflow, which emails the reply and marks the ticket sent.
6. A **Shopify** workflow keeps orders in sync (HMAC verified), a **backlog sweep** retries anything stuck, and an **error workflow** records failures.

## Stack

| Layer | Tech |
|---|---|
| Agent | Claude API (`claude-opus-5-5`), Anthropic TypeScript SDK tool runner, structured outputs, strict tools, prompt caching, refusal fallback |
| Data and security | Supabase Postgres, Row Level Security, column grants, security definer RPCs, triggers, pg_net, Realtime, Auth |
| Serverless | Supabase Edge Functions (Deno) |
| Automation | n8n: webhooks, Code nodes, HTTP retries, schedule trigger, error workflow, SMTP |
| Dashboard | Next.js 16 (App Router, Server Actions, `proxy.ts`), Tailwind CSS, `@supabase/ssr`, Vercel |
| Tests | pgTAP for RLS, `tsc`, `deno check` |

## Run locally

Requires Docker Desktop, Node 20+ and an Anthropic API key.

```bash
npm install
npx supabase start                      # Postgres, Auth, Realtime, edge runtime (applies migrations and seed)
npx supabase status                     # copy the API URL, anon key and service role key

cp .env.example .env.local              # fill NEXT_PUBLIC_SUPABASE_ANON_KEY and TRIAGE_WEBHOOK_SECRET
cp supabase/functions/.env.example supabase/functions/.env   # ANTHROPIC_API_KEY and TRIAGE_WEBHOOK_SECRET
npx supabase functions serve --env-file supabase/functions/.env

cp n8n/.env.example n8n/.env            # service role key and the same secrets
docker compose up -d
docker compose exec n8n n8n import:workflow --separate --input=/workflows
# In the n8n editor (http://localhost:5678): add an SMTP credential named "Support SMTP", then activate the workflows.

npm run dev                             # http://localhost:3000
INBOUND_WEBHOOK_SECRET=... node scripts/send-demo-messages.mjs
```

Local test users are listed at the top of `supabase/seed.sql` (local stack only).

## Deploy

- **Supabase:** `npx supabase link`, `npx supabase db push`, `npx supabase functions deploy triage`, `npx supabase secrets set ANTHROPIC_API_KEY=... TRIAGE_WEBHOOK_SECRET=...`, then set `private.settings` to the production n8n URL and secret.
- **n8n:** import the workflows on n8n Cloud or a self-hosted instance and set the same environment values (or move them to n8n credentials).
- **Vercel:** import the repo, set the variables from `.env.example`. Pull requests get preview deployments, `main` goes to production.
