# n8n workflows

Generated by `python n8n/build_workflows.py` into `workflows/`. Edit the generator, not the JSON, so the Supabase headers, retries and the error workflow wiring stay consistent.

| File | Trigger | What it does |
|---|---|---|
| `1-inbound-message.json` | `POST /webhook/support/inbound` | Validates the shared secret and fields, stores the ticket idempotently (`rpc/ingest_ticket`), answers 202, runs the triage agent for new tickets |
| `2-send-approved-reply.json` | `POST /webhook/support/approved` from the Postgres approval trigger | Re-reads the ticket, sends the approved reply by SMTP, marks it sent, logs the event |
| `3-shopify-order-sync.json` | Shopify `orders/create` and `orders/updated` | Verifies the HMAC on the raw body, maps the order, upserts it (`rpc/sync_order`) |
| `4-backlog-sweep.json` | Every 5 minutes | Retries triage for tickets still `new` after 2 minutes |
| `5-error-handler.json` | Any failed execution | Writes the failure to `automation_errors` |

All workflows except the error handler point to it as their error workflow. Environment values used through `$env` are listed in `.env.example`; on n8n Cloud, move the secrets to credentials.

Load them into the local instance (from the repo root, after `npx supabase start` and `docker compose up -d`):

```bash
bash n8n/setup-local.sh
```

It imports the SMTP credential in `credentials/local-smtp.json` (the Mailpit inbox from `supabase start`, no password), imports the workflows, publishes all five and restarts n8n. The error handler has to be published too, or n8n skips it.
